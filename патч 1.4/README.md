# НарядAI 1.5 — ПК, мобильный веб и общая БД

Голосовой ввод отчётов: в ПК-приложении — дополнительное локальное распознавание, в мобильном вебе/PWA — распознавание браузера с явным согласием. Текст проверяется пользователем и добавляется в существующие поля; отправка отчёта остаётся отдельным действием. [Установка и проверка](docs/VOICE_INPUT.md).

Заказчик кейса №1: **АО «Костанайские минералы»**. Актуальная ветка — `cloud-1.4`; папка приложения по-прежнему называется `патч 1.4`. Сервер, настольный клиент и веб/PWA используют одну модель нарядов и миграцию БД **002**.

## Быстрый запуск на Windows

Распакуйте репозиторий и сохраните обе папки `патч 1.4` и `database`: импортёр использует соседний архив БД. Если путь слишком длинный для PySide6, `install.bat` автоматически создаёт окружение в короткой папке `%USERPROFILE%\.nai\<идентификатор>`. База, фото и настройки приложения остаются в проекте. Права администратора и изменение настроек Windows для этого не нужны.

Установщик сохраняет выбранное окружение только после проверки зависимостей. `start.bat`, сервер, клиент, обработчик ИИ и установка голоса используют этот выбор. Старую частично установленную `.venv` не нужно переносить или удалять. После переноса проекта снова запустите `install.bat`. Проверка без установки: `py -3 tools\install.py --check`.

Для ПК запустите `install.bat`, затем `start.bat`. Для браузера достаточно `install_web.bat`, затем `start_web.bat`. Новая маленькая демо-база: логины `master`, `worker1`–`worker15`, `admin`, `manager`, пароль `1234`. ИИ в демо выключен; окончательную оценку выставляет мастер.

## Демонстрация с полной учебной базой

В PowerShell из папки приложения после установки:

```powershell
py -3 tools\run.py tools\import_demo.py --data-dir demo_dataset
py -3 tools\run.py main.py --data-dir demo_dataset
```

Для веб-версии:

```powershell
py -3 tools\run.py --web-first run_demo.py --dataset --data-dir demo_dataset
```

Откройте `http://127.0.0.1:8841`. Для веба сначала используется `.webvenv`, затем выбранное окружение настольной версии. Также работает `start_web.bat --dataset --data-dir demo_dataset`.

Полный набор: 608 нарядов, 655 версий отчётов, 705 учебных JPEG, история трёх месяцев, 4 участка, 25 единиц оборудования, 2 мастера, 15 сотрудников, 3 бригады, 20 дефектов и 40 материалов. Фото — учебные карточки, оценки модели синтетические.

Логины: `master`, `master2`, `worker1`–`worker15`, `admin`, `manager`. **Пароль полного набора: `DemoOnly-2026!`**, он отличается от маленькой демо-базы. Учебные учётные записи предназначены для демонстрации.

Импортёр принимает только новую пустую папку. Повторный запуск с тем же набором сохраняет внесённые действия. Существующая чужая база не заменяется. При первом запуске приложение обновляет импортированную SQLite до 002 и сохраняет резервную копию.

## Общий сервер и PostgreSQL

Установите `requirements-server.txt`. Для локального сервера настройте `server_config.json` через `tools/setup_server.py` и запустите `run_server.py`. Для общего ПК-клиента используйте `start_client.bat` и адрес сервера; браузер открывается по этому же адресу.

PostgreSQL/Supabase: [инструкция пакета БД](../database/README.md), [миграция, API и настройки](docs/DATABASE_V2.md). Импортируется полный baseline и миграция 002, а не только `schema.sql`. Секреты, URL БД и ключи Storage хранятся в локальной конфигурации/переменных окружения.

Для существующей базы обновление применяет миграцию с сохранением записей и паролей; учебный импорт не нужен. Перед обновлением рабочего сервера сохраните резервные копии БД и фотографий.

Docker включает каталог `web`. Render использует ветку `cloud-1.4`, Root Directory `патч 1.4`, build `pip install -r requirements-server.txt`, start `python run_server.py`. Код в GitHub сам по себе не разворачивает облачную базу.

## Проверки

```powershell
python -m pip install -r requirements-test.txt
python -m unittest discover -s tests -p "test_*.py"
node --check web/app.js
node --check web/sw.js
node tests/check_web_rpc.js
```

Тесты работают с временными SQLite и учебными данными. PostgreSQL проверяется отдельно в специально выделенной локальной тестовой БД через `TEST_DATABASE_URL`; не задавайте рабочую БД. Старые `check_*.py` от прототипа 1.4 сохранены для истории; текущий набор регрессий — `test_*.py` и `check_web_rpc.js`.

На реальном оборудовании остаются проверка Android/PWA по HTTPS, камеры, push, облачной PostgreSQL/Storage, нагрузки и точности модели. APK этим объединением не создаётся.
