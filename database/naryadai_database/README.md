# НарядAI: PostgreSQL и интеграция, кейс №1 АО «Костанайские минералы»

Версия приложения 1.5, миграция `002`. Изменения предназначены для `MrAngelskye/hakaton`, ветки `cloud-1.4`, папки `патч 1.4`. Код приложения обновлён вместе с этим пакетом. После получения новой версии ветки отдельный интеграционный патч применять не требуется.

Все сведения, изображения, цены и оценки ИИ учебные. Фото — подписанные карточки, а не фотографии предприятия. Нормативы предприятия и формулу рейтинга необходимо согласовать с ментором. Источник требований — [кейс №1](https://drive.google.com/drive/folders/1Xx-QKkGMSk2Df6X9jIH2TbpQxZI_zaV1?usp=sharing).

## Изменения

Полный процесс наряда, четыре приоритета, история исполнителей/бригад, фактические времена, ночные смены, обязательное фото после внепланового ремонта, нормализация единиц материалов, каталоги по ID, нормативы, отдельный учёт простоя оборудования, периодная аналитика и составной рейтинг. Уведомления хранятся в outbox с повторной доставкой и подтверждением прочтения; для Android push нужен внешний провайдер. ИИ получает нормативы, технические предупреждения и фото; окончательное решение остаётся за мастером.

RPC фиксирует действие и квитанцию одной транзакцией; повтор с тем же ID и содержимым безопасен. Сервер использует пул PostgreSQL, пакетные выборки и постраничный архив. Подробности и API: `DATABASE_V2.md` в пакете или `патч 1.4/docs/DATABASE_V2.md` в репозитории.

## Первое развёртывание PostgreSQL

Используйте отдельную пустую БД. Установите зависимости приложения из `requirements-server.txt`, зависимости импортёра — из `requirements.txt` этого пакета. Задайте `DATABASE_URL` на своей машине. Для удалённой БД требуется TLS; не добавляйте секреты в репозиторий.

```powershell
python load_postgres.py
```

Импортёр создаёт baseline, импортирует набор и применяет 002. Повтор с тем же ID не перезаписывает действия приложения; другой набор или чужая БД отклоняются. Прямое выполнение только `schema.sql` и `seed.sql` оставляет baseline 001; миграцию завершает импортёр или новая версия сервера.

Для фото задайте `SUPABASE_URL`, `SUPABASE_SECRET_KEY` и выполните:

```powershell
python load_postgres.py --upload-photos --bucket naryadai-reports
```

Без этого флага импортируются только метаданные. Файлы должны попасть в приватный bucket отдельно; публичный bucket импортёр отклоняет. Подключение сервера и удалённого ИИ описано в README приложения. Размещение кода на GitHub само по себе не разворачивает PostgreSQL.

## Обновление текущей базы и перенос SQLite

Остановите старое приложение, сохраните резервную копию БД и фото, обновите код и зависимости. При старте новая версия применяет 002 к существующей SQLite или PostgreSQL без загрузки демонстрационного набора. SQLite дополнительно сохраняет `naryadai-before-v2.db`. Неизвестные старые названия сохраняются как `LEGACY-*`; восстановленные времена явно помечаются как приблизительные исторические данные.

Для переноса вашей SQLite в пустую PostgreSQL используйте инструмент из приложения:

```powershell
python tools/migrate_sqlite_to_postgres.py "путь/к/naryadai.db" --backup-dir "новая-папка-копии"
```

Он сохраняет ID, историю и копию фото с контрольными суммами. Добавьте `--upload-photos` при настроенном Supabase Storage. Активные сессии не переносятся. Вход, фото, создание/закрытие наряда и аналитику проверьте после переноса.

Для просмотра учебной SQLite скопируйте всю `generated/` в отдельную папку и запустите `main.py --data-dir "папка-копии"`. Рабочую SQLite не заменяйте учебной.

## Патч старой копии кода

Предпочтительно получить обновлённую ветку. Если у вас сохранилась исходная копия указанного базового коммита:

```powershell
python apply_integration.py --project-dir "путь/к/патч 1.4"
```

Установщик заранее проверяет все хеши, сохраняет изменяемые файлы с суффиксом `.before-db-integration`, добавляет новые модули и допускает повторный запуск. При изменённых командой исходниках останавливается до записи: переносите diff вручную с сохранением своих правок. Сам установщик не изменяет БД.

## Проверки и оставшиеся работы

Результаты SQLite, API через PostgreSQL-протокол, SQL-ограничений, Qt, импортёра, установщика и переноса находятся в `validation.json` и приложенных JSON. PostgreSQL-проверки использовали PGlite 0.5.8, хранилище — локальные файлы/память; реальное облако и модель не участвовали. Один нативный SQL-тест в каждом запуске Python пропущен; ограничения отдельно проверены непосредственно в SQL-движке.

На сервере команды остаются проверка настоящей PostgreSQL под параллельной нагрузкой, восстановление PostgreSQL/Storage, мобильная доставка, точность модели и реальных нормативов. Android/PWA, PDF/XLSX, интеграция ERP/1С и прогноз отказов не реализованы этим обновлением. CSV и API доступны. Права промышленной рабочей роли и политики предприятия нужно настроить отдельно от текущего API владельца схемы.
