# НарядAI · Allur — интерактивная UI beta

Рабочий веб-прототип с интерфейсом под Android. Без backend, реальной авторизации и вызовов ИИ. Создан для согласования экранов с капитаном команды и передачи программисту. Синяя, тёмно-фиолетовая и белая палитра; на телефоне — нижняя навигация, на компьютере — боковая.

## Запуск

Самый простой способ: открыть `dist/index.html` в современном браузере. Для стабильного сохранения данных рекомендуется локальный сервер:

```powershell
node serve.mjs
```

Открыть `http://127.0.0.1:5173/`. Нужен Node.js; устанавливать пакеты не требуется. Альтернатива при установленном Python: `python -m http.server 5173 --bind 127.0.0.1 --directory dist`.

На телефоне можно открыть опубликованную ссылку в браузере. Это веб-прототип, а не APK. Производственные участки, оборудование, сотрудники, оценки и наряды — вымышленные примеры для Allur, не данные завода. Дата демонстрационной смены зафиксирована: 2 октября 2026 года, 08:00–18:00.

## Как посмотреть полный сценарий

1. Выбрать «Сотрудник». Оставить имя «Александр Иванов» и PIN `1234`.
2. Выбрать доступную задачу. Указать время и нажать «Взять в график».
3. Открыть «График»: наряд появится в выбранном интервале. До начала работы можно изменить время или убрать задачу из графика.
4. Открыть наряд → «Приступить» → «Заполнить отчёт». Указать работы, время, дефект, материалы и при желании фотографии. Отправить мастеру.
5. Нажать на инициалы справа вверху → «Сменить роль / выйти». Выбрать «Мастер».
6. В «Отчётах» открыть новый результат, выставить оценку и написать комментарий. Принять или вернуть на доработку.
7. Вернуться в роль сотрудника с тем же именем. Решение появится в отчёте. Принятая работа обновит его статистику и рейтинг; возвращённый отчёт можно исправить и отправить снова.

PIN принимает любые четыре цифры. Имя используется как идентификатор демонстрационного сотрудника: чтобы вернуться к тем же нарядам, вводите то же имя. Это способ переключения макета, не механизм контроля доступа.

## Готовые экраны и действия

| Роль | Вкладки | Рабочие действия |
|---|---|---|
| Сотрудник | Задачи, График, Отчёты, Профиль | Поиск по наряду, оборудованию и участку; фильтр срочных задач; выбор и начало задачи; изменение времени; отправка отчёта и фото; повторная отправка после доработки; обратная связь, статистика и рейтинг |
| Мастер | Смена, Задачи, Отчёты, Команда | Создание наряда; поиск и просмотр состояния задач; принятие отчёта; редактирование оценки; комментарий; возврат на доработку; просмотр статистики отдельного сотрудника |
| Администратор | Заглушка | Демонстрационный вход, надпись «пока не готова», смена роли |

Уведомления и меню аккаунта открываются кнопками в верхней панели. Сброс начального примера доступен в меню аккаунта с подтверждением. Все изменения локальные: вкладки и роли этого браузера используют один набор данных, другие устройства его не получают.

## Состояния для программиста

```text
available → planned → inProgress → submitted → approved
                                      ↓
                                   revision → submitted
```

`available` — доступна всем сотрудникам; `planned` — выбрана в график; `inProgress` — работа начата; `submitted` — отчёт у мастера; `revision` — возврат с комментарием; `approved` — работа принята.

Время выбирается с шагом 30 минут. В интерфейсе доступны только интервалы без пересечений, полностью помещающиеся в смену. Параллельное редактирование несколькими браузерными вкладками не реализовано. Плановая задача может быть возвращена в общий список. Отправленный отчёт изменяется сотрудником только после возврата мастером.

Средняя оценка сотрудника — арифметическое среднее оценок его принятых отчётов. Рейтинг сортируется по этому среднему. Сотрудник без принятых отчётов имеет оценку «—». Время статистики — сумма фактических часов принятых отчётов, загрузка графика — сумма планового времени. Это демонстрационная формула, её можно заменить согласованной командой.

## ИИ-агенты

Реальных ИИ-вызовов нет. В двух начальных отчётах мастер может раскрыть **«Пример заключения ИИ · Демо»**: локальный агент, DeepSeek для расчётов и второй агент, который пока не выбран. Заключение подписано «От имени администратора · статический пример». Новые отчёты получают надпись «Отчёт без ИИ-проверки» и ручную оценку мастера. Кабинет администратора остаётся заглушкой, как запрошено.

## Файлы и дальнейшее подключение

- `dist/index.html` — оболочка страницы, метаданные и диалог.
- `dist/styles.css` — цветовые токены, компоненты, мобильные размеры, анимации.
- `dist/ui.js` — демонстрационные данные, рендер экранов, переходы и локальные действия.
- `serve.mjs` — необязательный локальный статический сервер, без API и базы.

Данные хранятся под ключом `naryadai-allur-demo-v1` в `localStorage`; роль текущей сессии — в `sessionStorage`. `seedState()` создаёт пример, `save()` сохраняет локальные изменения, `render()` обновляет экран. При закрытии вкладки роль сбрасывается, наряды сохраняются. Фотографии сжимаются на устройстве до 800 px по длинной стороне; допускаются до 3 файлов JPG/PNG/WebP, до 8 МБ каждый. При заполненном хранилище изменения останутся только в памяти текущей страницы, что обозначается уведомлением.

Точки для будущего API: вход, получение списка задач, взятие наряда, изменение времени, начало выполнения, отправка отчёта/фото, решение мастера, создание задачи и получение статистики. Сейчас действия объединены с UI для простой демонстрации. Перед подключением сервера их стоит вынести в отдельный слой, а проверки ролей и конфликтов выполнять на сервере. Для нативного Android-клиента использовать этот прототип как карту экранов и состояний.

В поддерживающих браузерах предусмотрены два необязательных WebMCP-инструмента: чтение демо-смены и переход на доступную вкладку. Их контракт проверен с тестовой реализацией API; проверка в нативном WebMCP-окружении недоступна. Обычный интерфейс от WebMCP не зависит.

## UI/UX и проверка

Анимации: появление экрана и карточек, открытие нижнего диалога, смена активной вкладки, заполнение графиков, отклик кнопок. Длительность 180–500 мс. При `prefers-reduced-motion` отключаются. У диалогов есть закрытие кнопкой, Escape и нажатием на фон; формы имеют подписи и базовую валидацию, фокус клавиатуры видим. Основные кнопки рассчитаны на касание.

Проверено в Edge на мобильных размерах 390×844 и 360×800, на компьютере 1440×960. Пройдены входы во все роли, поиск и фильтр, взятие задачи, отсутствие пересечений графика, изменение времени, сохранение после перезагрузки, фото и отправка отчёта, принятие и возврат мастером, повторная отправка, создание задачи и просмотр статистики. Ошибок JavaScript в этом проходе нет. Проверка на физическом Android-устройстве и интеграция с backend ещё впереди.
