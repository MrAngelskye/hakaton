# Мобильный и веб-интерфейс НарядAI

Интерфейс без сторонних JavaScript-библиотек работает на том же Python/FastAPI-сервере, что и настольный клиент. Корень `/` — вход и приложение. `/web/*` — общедоступная оболочка. `/sw.js` — service worker с областью `/`. `/assets/branding/km-logo-white.svg` — логотип АО «Костанайские Минералы».

## Основные сценарии

- Мастер: обзор смены, быстрая выдача по участку/оборудованию/исполнителю/нормативу/приоритету, загрузка сотрудников, переназначение до начала, приёмка с комментарием и своей оценкой, история оборудования.
- Сотрудник: принять, поставить в очередь, отказать с причиной, начать, приостановить с причиной, продолжить, заполнить результат и материалы, снять фото, отправить, получить замечание и доработать. Самостоятельный выбор доступной работы — дополнительный путь.
- Администратор: пользователи, включение/отключение доступа, связанные справочники участков, оборудования, бригад, неисправностей, материалов и нормативов.

Данные справочников помечены как демонстрационные. Их необходимо заменить согласованными данными организатора перед эксплуатацией.

## API-контракт

- `POST /api/login` с `{username,password,role}` возвращает `{token,user}`. Роли `worker/master/admin`.
- Авторизация: `Authorization: Bearer ...`. Токен хранится в `sessionStorage`, а не в постоянном localStorage.
- `GET /api/snapshot?day=YYYY-MM-DD`: `tasks,reports,users,shifts,free_slots,employee_status,ai_enabled`; дополнительно `references,alerts,attention`.
- `POST /api/call/<method>`: `{args,kwargs,request_id,photos}` → `{result}`. Правила доступа, справочники и допустимые переходы проверяются сервером.
- `GET /api/photos/<name>`: авторизованный запрос, затем локальный `blob:` URL только в памяти страницы. Эти ответы никогда не кэшируются service worker.
- Категории справочников: `sites/equipment/brigades/defects/materials/normatives`. Ключи записей — целые `id`; оборудование и бригады имеют `site_id`, у бригад `members`.

Все отображаемые названия, описания и результаты экранируются. Веб-клиент не содержит ключей AnythingLLM, PostgreSQL или Supabase.

## Черновики и сеть

Фотоотчёт сохраняется в IndexedDB под ключом пользователя и наряда. Фотографии остаются исходными, без перекодирования. Перед транспортом сохраняется точный запрос и его `request_id`. Если ответ потерян, пользователь повторяет тот же запрос: серверная идемпотентность предотвращает второй отчёт. После ответа с ошибкой валидации поля снова доступны для исправления. При отсутствии сети показано предупреждение; отправка не считается успешной без ответа сервера.

Выход удаляет все локальные черновики, сеанс и временные URL фото. Не храните производственные фото на общедоступном устройстве вне рабочего сеанса. Обновление снимка раз в 3 секунды не заменяет открытую форму, фокус и незаполненные поля.

Для остальных операций интерфейс хранит ожидающие идентификаторы запросов только в памяти текущего сеанса: повтор того же действия после потери ответа или HTTP 5xx использует прежний `request_id`. Успех и ошибка валидации очищают запись. Перезагрузка страницы очищает эту память; постоянное восстановление предусмотрено только для отправляемого фотоотчёта. Серверные сбои между изменением данных и фиксацией квитанции остаются отдельным ограничением и не являются гарантией exactly-once.

Service worker сохраняет только публичную оболочку. **Полной офлайн-синхронизации нет**: без сети доступны оболочка и локальный черновик в текущем сеансе; вход, список новых нарядов, фото сервера и отправка требуют сети. Отправки в фоне нет.

## Установка PWA

Для установки и service worker требуется **HTTPS** (или localhost на этом же компьютере). Адрес `http://192.168...` на Android позволяет использовать обычную веб-страницу, но не гарантирует PWA-установку, безопасные функции и работу service worker. Для проверки телефоном используйте HTTPS-развёртывание или локальный сертификат, которому доверяет тестовый телефон.

Android Chrome: меню → «Установить приложение»; кнопка в настройках появляется, когда браузер отдаёт событие установки. Установка не создаёт APK. Если нужен именно APK, это отдельная упаковка и тестирование.

Стили адаптированы для мобильного экрана и ПК. Touch-кнопки не меньше 48 px. Цветные статусы дублируются словами. Есть клавиатурный фокус, skip-link, live-уведомления, нативные модальные диалоги. Системное уменьшение анимаций учитывается; переключатель в настройках сохраняется локально.

## Проверка

`python tests/check_web.py` проверяет статический контракт оболочки, manifest, существование ресурсов и ограничения кэширования. `node --check web/app.js` и `node --check web/sw.js` проверяют синтаксис. Эти проверки не заменяют ручной проход на реальном Android и проверку камеры/PWA на HTTPS.

`node tests/check_web_rpc.js` исполняет фактическую RPC-функцию клиента в Node VM: потеря уже принятого ответа, HTTP 503, сброс после HTTP 400, другое содержимое запроса, постоянный идентификатор фотоотчёта и очистка после успеха. Сетевые ошибки в этом тесте имитируются; это не проверка Android-сети.

Рекомендуемый проход: мастер выдаёт → сотрудник принимает → старт → пауза с причиной → продолжение → форма+фото → закрыть и восстановить черновик → отправить → мастер вернуть с комментарием → сотрудник доработать → мастер принять со своей оценкой. Отдельно: обрыв сети при отправке, повтор без дубликата, выход и отсутствие чужого черновика, отключённый ИИ и ручная приёмка.
