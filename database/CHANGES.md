# Выполненные изменения по аудиту кейса №1

Приложение 1.5 и миграция 002 для `MrAngelskye/hakaton`, ветки `cloud-1.4`. Базовая версия аудита — `bc429752b61974e902841b38361f2d2a5be91759`. Изменения охватывают схему, пути записи сервера и Qt-интерфейс; подготовлен полный интеграционный diff и обновлённый учебный архив.

| Замечание аудита | Исправление |
| --- | --- |
| Нет принятия, очереди, отказа и четырёх приоритетов | Новые состояния, причины и действия доступны через API и интерфейс |
| Журнал новых действий не хранит факты | Фактические времена и типизированные события; прямые SQL-изменения PostgreSQL получают аудит |
| Переназначение ломает старые отчёты | История назначений; отчёт сохраняет автора, бригаду и версию независимо от нового ответственного |
| Ночные смены и бригадные назначения не поддерживаются | Переход через полночь, проверка соседних дат и резервирование участников бригады |
| Можно закрыть ремонт без обязательного фото | Закрытие внепланового отчёта требует фото после; метаданные, контроль повторов и времени, загрузка до блокировки БД |
| Справочники и единицы вводятся произвольно | ID оборудования/дефектов/материалов, преобразование единиц, каталог цен и нормативы расхода |
| Контроль сроков существует только как таблица | Планировщик 10/3/30 минут, outbox, внутренние уведомления, подтверждение и повторная доставка через необязательный webhook |
| Аналитика и рейтинг неполные | Фильтры периода/участка/оборудования/работника/бригады; пять компонентов рейтинга, подтверждённые повторы и оценённые отказы |
| Пауза смешивается с простоем | Отдельные интервалы простоя, объединение пересечений и причины |
| Чат не получает факты БД | Проверенные недельные агрегаты и статусы с анонимными ID; роль руководителя с доступом к чтению |
| RPC может продублировать действие | Запись действия и квитанции в одной транзакции; привязка request_id к содержимому |
| Панель создаёт сотни запросов/соединений | Пул PostgreSQL, пакетные оценки ИИ, ограничение истории, постраничный архив, сжатие HTTP |

Для SQLite предусмотрены автоматическая резервная копия и миграция с проверкой внешних ключей. Инструмент переноса в пустую PostgreSQL сохраняет ID, историю и копию фото с контрольными суммами. Новые производственные нормативы не выдуманы: их задаёт команда по данным ментора.

Проверено локально: по 16 выполненных регрессионных тестов для SQLite и API через PostgreSQL-протокол; по одному SQL-тесту пропущено из-за ограничения socket-адаптера PGlite. Отдельно прошли все 16 проверок SQL, четыре проверки Qt/подготовки фото, начальный и повторный импорт, установщик и перенос SQLite. Перенос сохранил 19 пользователей, 609 нарядов, 656 отчётов и 705 записей фото, включая добавленные тестовые действия. Учебный архив содержит исходные 608 нарядов и 655 отчётов.

В проверенном снимке панели PostgreSQL выполнено 33 SQL-запроса; тело ответа 393 941 байт при 122 видимых нарядах и 101 отчёте. Это локальное наблюдение, не гарантия задержки в облаке. История и доступность сотрудников вычисляются независимо от ограничения размера страницы.

Проверки использовали PGlite 0.5.8 и локальное/тестовое хранилище. Настоящая PostgreSQL, параллельная нагрузка, восстановление облачной БД/Storage, Android push и точность реальной модели ещё требуют проверки. Android/PWA, PDF/XLSX, ERP/1С и прогноз отказов остаются отдельными задачами; CSV и API доступны. Формулу рейтинга и нормативы необходимо утвердить с ментором. Рабочая БД команды этим коммитом автоматически не разворачивается.

Инструкция: `патч 1.4/docs/DATABASE_V2.md`. Результаты и архив: `database/naryadai_database/validation.json`, `database/naryadai_database.zip`.
