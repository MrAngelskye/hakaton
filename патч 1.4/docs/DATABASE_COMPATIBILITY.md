# Совместимость последнего пакета БД с MVP

Проверено 4 октября 2026. Ветка `codex/mvp-flow` включает обновление команды
`cloud-1.4 / bc42975`: папку `database/` с отдельной схемой и синтетическим набором.
Файлы этого пакета сохранены без изменений. Его SQL и скрипт интеграции не запускались.

## Что использовать для показа текущего MVP

`install_web.bat` → `start_web.bat` создаёт отдельную SQLite-базу `demo_data`.
Для аналитики: `start_web.bat --history --data-dir demo_history_data` в новой папке.
Этот режим добавляет 540 явно синтетических нарядов за 90 дней, без фото и ответов
ИИ. Он проверен с текущими статусами, справочниками и интерфейсом.

Облачный адаптер приложения создаёт собственную схему `naryadai` на пустой БД.
Инструкции README относятся к этому пути. Реальный PostgreSQL/Supabase/Render
после изменений MVP ещё требует отдельного прогона.

## Почему отдельный пакет нельзя сразу подключить к этому MVP

Пакет `database/naryadai_database` рассчитан на исходники `8369615`.

| Различие | Последствие | Работа для совместимости |
|---|---|---|
| Ограничения `tasks.priority` допускают `urgent/normal` | Новые `high/routine` отклоняются | Проверенная миграция ограничений |
| Ограничения статуса не допускают `issued/accepted/queued/rejected` | Новый путь выдачи не сохраняется | Согласовать статусы и обновить ограничения |
| Нативные `DATE/TIMESTAMPTZ/JSONB` | Текущий контракт Store ожидает ISO-строки и сериализованный JSON | Перенести нормализатор `Row/Cursor` из пакета, сохранив изменения MVP, и протестировать |
| Отдельные таблицы участков, оборудования, материалов и бригад | Они не совпадают с текущим `reference_items` | Сопоставить ключи и связи; проверить импорт нарядов |

SQLite-набор, генерируемый этим пакетом, также содержит прежние ограничения.
Он подходит для отдельной проверки исходной версии, но не является готовой
базой нового рабочего процесса. Автоматического импорта этого набора в MVP нет.

`apply_integration.py` проверяет хэши четырёх файлов. На изменённых MVP-исходниках
он остановится. Старый `integration.patch` не следует накладывать целиком:
его изменения справочников уже заменены текущими связанными справочниками.

`load_postgres.py` не выполняет DROP/TRUNCATE, но на существующей versioned-схеме
может обновить функции, триггеры и представления до отказа из-за другого набора.
Для независимого теста пакета нужна отдельная пустая тестовая БД и отдельная
переменная, например `DEMO_DATABASE_URL` через `--database-env`.
Не направляйте этот тест на БД работающего MVP.

Отдельный следующий этап: миграция ограничений, нормализация типов, сопоставление
справочников, затем прогон выдачи, фотоотчёта, ИИ, приёмки и повторного запуска
на настоящей тестовой PostgreSQL. До него готовность подключения пакета не заявляется.
