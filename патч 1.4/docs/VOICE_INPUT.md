# Голосовой ввод отчётов

Диктовка помогает заполнить «Выполненные работы» и «Результат контрольной проверки». Она не меняет шифры дефектов, количество материалов, время работы и оценку. Пользователь проверяет распознанный текст, особенно числа и технические названия. ИИ и мастер получают обычный текстовый отчёт через существующий API; миграция БД не нужна.

## Как пользоваться

1. Открыть форму отчёта о выполнении наряда.
2. Нажать «Диктовать» для нужного поля, затем «Начать диктовку».
3. Продиктовать сведения и нажать «Остановить». Один сеанс ограничен двумя минутами; продолжение запускается вручную.
4. Исправить текст в предпросмотре и нажать «Добавить в отчёт». Существующее содержимое поля сохраняется, добавленный текст записывается в черновик прежним механизмом.
5. Проверить остальные поля и фотографии, затем отдельно отправить отчёт мастеру.

Предпросмотр ещё не является сохранённым текстом отчёта. Перед сохранением или отправкой нужно добавить его либо отменить диктовку. Отмена не стирает ранее заполненные поля. Закрытие формы и выход выключают микрофон; результаты прежней сессии не попадают в другой отчёт.

## ПК: локальное распознавание

После обычной установки приложения запустить `install_voice.bat` из папки `патч 1.4`. Дополнительная установка скачивает Vosk, sounddevice и русскую модель `vosk-model-small-ru-0.22` с официального сайта, около 45 МБ. Интернет нужен для первоначальной установки. При самой диктовке аудио не сохраняется и не передаётся в AnythingLLM, Qwen или сторонний сервис.

Модель обычно хранится в `%LOCALAPPDATA%\NaryadAI\voice_models\vosk-model-small-ru-0.22`, отдельно от БД. Уже распакованную модель можно выбрать кнопкой «Выбрать локальную модель». На Windows для библиотеки распознавания используется короткое имя существующего пути, чтобы поддержать кириллицу. Если такой путь недоступен, нужно выбрать модель в короткой папке с латинскими именами; настройки системы автоматически не меняются.

Без дополнительных пакетов или модели приложение продолжает запускаться, ручной ввод работает. Ошибка микрофона, модели или перегрузка распознавания отображаются в форме. Во время загрузки модели можно отменить диктовку: микрофон не включится после закрытия окна.

Дополнительные команды из папки приложения:

```text
.venv\Scripts\python.exe tools\setup_voice.py --check
.venv\Scripts\python.exe tools\setup_voice.py --model-only
.venv\Scripts\python.exe tools\setup_voice.py --model-only --target C:\NaryadAI\voice_models\vosk-model-small-ru-0.22
```

`--check` ничего не скачивает. `--target` задаёт конечную папку модели; её можно затем выбрать в приложении. Существующая неполная папка не перезаписывается. Большие модели не входят в Git.

## Android / мобильный веб

Работает в браузерах с `SpeechRecognition` или `webkitSpeechRecognition`, через HTTPS либо localhost. Установка PWA сама по себе не гарантирует поддержку диктовки. Перед первым запуском формы пользователь подтверждает, что голос может обрабатываться сервисом браузера; отказ оставляет ручной ввод. При сетевом распознавании нужен интернет. Аудио не сохраняется в БД приложения; правила обработки сервиса браузера определяются его поставщиком.

Если браузер не поддерживает API, не разрешает микрофон либо недоступен сервис, форма показывает объяснение. При переключении приложения микрофон останавливается; подтверждённый предпросмотр остаётся в открытой форме. Автоматического перезапуска записи нет. Мобильный вариант пока не следует считать локальным распознаванием без интернета.

## Проверка

```text
python -m unittest discover -s tests -p "test_*.py"
node tests/check_voice.js
node tests/check_voice_integration.js
```

Для браузерных тестов нужен Playwright и доступный Chromium. Можно задать `NARYADAI_TEST_BROWSER` с путём Chrome/Edge; `CODEX_PRIMARY_RUNTIME_NODE_MODULES` позволяет использовать пакет из runtime Codex. Тесты используют имитацию речи, не включают настоящий микрофон. Проверяются отмена, поздние ответы, сохранение черновика, предел текста, повторные результаты, ошибки, блокировка отправки и восстановление замороженного запроса.

Проверка на реальном устройстве перед показом: разрешение микрофона; короткая и длинная русская фраза с названиями узлов и числами; остановка; редактирование; закрытие и повторное открытие отчёта; ошибка/отказ доступа; отправка текста и приёмка мастером. Для ПК дополнительно проверить диктовку без интернета; для Android — Chrome и установленную PWA, переключение приложения и шумный фон. Автоматические проверки не измеряют точность речи в условиях предприятия.

Источники: [официальные модели Vosk](https://alphacephei.com/vosk/models), [пример захвата микрофона Vosk](https://github.com/alphacep/vosk-api/blob/master/python/example/test_microphone.py), [SpeechRecognition и ограничения браузеров](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition).
